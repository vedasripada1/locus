# Locus

A local-first web app that reads an **AncestryDNA** or **23andMe** raw data file and produces a transparent, evidence-linked report. It covers clinically relevant variants (ClinVar/ClinGen), common-variant associations (NHGRI-EBI GWAS Catalog), metabolism and performance traits, and a literature-backed list of "possible actions to discuss".

Every statement in the report is either a fixed template or a value copied from a source record, with a link to that record. Nothing is generated by an LLM.

> **Not a medical device.** Consumer raw data contains errors and cannot establish or rule out a diagnosis. Potentially serious findings must be confirmed by clinical-grade testing and discussed with a genetics professional.

## Quick start

```bash
npm install
npm run dev            # http://127.0.0.1:5173. Click "Demo 23andMe" / "Demo AncestryDNA", or open /#demo=23andme
npm test               # 28 unit tests: parsing, allele matching, interpretation, claim verification
npm run build          # typecheck + production build (adds a strict CSP, see Privacy)
npm run preview -- --port 4317 --strictPort &   # serve the build
npm run smoke          # headless-Chrome check of the build: renders, no errors, no network, delete works
```

The evidence bundle (`src/evidence/bundle.json`) and the synthetic demo files are committed, so the app runs without network access. Rebuild the evidence only when you want fresh data:

```bash
export NCBI_EMAIL=you@example.org       # optional; NCBI asks tools to identify themselves
export NCBI_API_KEY=...                 # optional; raises the NCBI limit from 3 to 10 requests/s
npm run evidence:all                    # fetch → literature → build (verify)
npm run demo:make                       # regenerate synthetic demo files from the new bundle
```

Requires Node 20+ (developed on Node 24). `npm run smoke` needs Google Chrome installed (set `CHROME_PATH` if it isn't in `/Applications`).

## How it works

```
 OFFLINE PIPELINE (node, needs network)                    BROWSER (no network)
 ┌───────────────┐   ┌──────────────────┐   ┌──────────┐    ┌────────┐  ┌───────┐  ┌───────────┐  ┌────────┐
 │ 1 fetch       │──▶│ 1b literature    │──▶│ 2 build  │──▶ │ parse  │─▶│ match │─▶│ interpret │─▶│ export │
 │ dbSNP ClinVar │   │ PubMed/PMC/FDA   │   │ verify + │    │ worker │  │       │  │           │  │ MD/JSON│
 │ ClinGen GWAS  │   │ candidates+texts │   │ audit    │    └────────┘  └───────┘  └───────────┘  └────────┘
 └───────────────┘   └──────────────────┘   └──────────┘
        pipeline/out/*.json        src/evidence/bundle.json (versioned, committed)
```

Each stage is a separate module with typed inputs and outputs (`src/core/types.ts`). See [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md) for the data model, the matching and interpretation rules, and how to extend coverage.

| Stage | Code | What it may do | What it may not do |
|---|---|---|---|
| Retrieval | `pipeline/fetch.ts`, `pipeline/literature.ts` | Copy records from sources, with URL, version and retrieval date | Interpret |
| Verification | `pipeline/build.ts` | Drop any curated claim whose quote isn't verbatim in the fetched source, or whose numbers aren't in its quote | Add claims |
| Matching | `src/core/match.ts` | Align alleles to the forward strand; flag missing, no-call, ambiguous and mismatched sites | Infer untested genotypes |
| Interpretation | `src/core/interpret.ts` | Apply documented rules to verified records | Create associations or effect sizes |
| Narrative | `src/core/export.ts`, `src/ui/*` | Fill fixed templates | Generate free text |

## Privacy

- **Local processing:** the file is parsed in a Web Worker in your browser tab. Only the curated sites are kept in memory; the raw text is discarded after parsing.
- **No network in production:** the production build ships `Content-Security-Policy: connect-src 'none'`, so the page cannot send data anywhere, even by mistake. The evidence and demo data are bundled into the app, and there are no web fonts or CDNs. `npm run smoke` asserts that zero external requests happen.
- **Nothing retained:** no localStorage, IndexedDB or cookies. Personal context fields live in memory only. **Delete my data** clears the genome, the context and the report. Closing the tab does the same.
- **No LLM:** no genotype or report content is sent to any model or external service.
- **Exports stay with you:** Markdown and JSON exports are written by your browser to your disk. The JSON contains findings, not the raw file.

| [dbSNP](https://www.ncbi.nlm.nih.gov/snp/) | Forward-strand alleles, GRCh37/38 positions, merged rsIDs, allele frequencies | Variation Services API | Public domain |
| [PubMed](https://pubmed.ncbi.nlm.nih.gov/) / [PMC](https://pmc.ncbi.nlm.nih.gov/) | Abstracts and full text for curated intervention claims; literature candidates | E-utilities | Abstracts © publishers; the app stores short verbatim quotes with citations |
| [FDA consumer update](https://www.fda.gov/consumers/consumer-updates/spilling-beans-how-much-caffeine-too-much) | Caffeine intake guidance | Page fetch | US government work |

Versions and retrieval dates for every record are in the bundle and shown under **Sources & audit**. The current bundle uses ClinVar updated 2026-09-14, GWAS Catalog release 2026-09-13, dbSNP build 157, and a ClinGen export from 2026-09-23.

### API and rate-limit notes

- **NCBI E-utilities / Variation API:** 3 requests/s without a key, 10 with `NCBI_API_KEY`. The client enforces a minimum gap (350 ms / 110 ms), sends `tool`/`email`, and retries 429/5xx with backoff. Python's default User-Agent receives 404s from E-utilities, so the pipeline sends its own UA.
- **GWAS Catalog REST v2:** undocumented limits and occasionally slow or HTTP 500 on large result sets (e.g. APOE). The pipeline uses 200-row pages, one request at a time, 300 ms spacing and retries. A site whose request still fails gets an audit warning and no associations, never an invented one.
- **ClinGen:** one CSV download per build.
- **Google Scholar is not used.** It has no API and forbids scraping. **NIH ODS** fact sheets and **NCBI Bookshelf** sit behind bot challenges, which the pipeline doesn't try to get around. The equivalent values were taken from PubMed/PMC (the IOM vitamin D report summary in PMC; the EFSA folate UL opinion).
- Responses are cached in `pipeline/cache/` (git-ignored) for `CACHE_MAX_AGE_DAYS` (default 30), so rebuilds are cheap and polite.

## What the report contains

1. **Clinically significant findings requiring confirmation:** a ClinVar Pathogenic/Likely pathogenic allele observed in your file. That means either the aggregate classification, or a per-condition classification with ≥2★ review status, and never when the aggregate is "conflicting". Inheritance comes from ClinGen (e.g. "autosomal recessive; one copy usually indicates carrier status"). Conflicting, uncertain, not-carried and **not-tested** sites are listed separately.
2. **Common disease associations (GWAS),** kept separate from ClinVar. Each shows your genotype, effect allele (and its forward-strand version), copies, OR or β with CI, p, lead study with sample and ancestry, a replication count, and strength (strong ≥3 concordant publications, moderate 2, limited 1, conflicting when ≥25% of associations disagree in direction). **No absolute risk is ever shown.**
3. **Metabolism** and 4. **Performance:** same format. Tested topics without genome-wide significant evidence say so explicitly. In the current catalog, ACTN3 R577X and CYP1A2 rs762551 have none for performance or caffeine traits.
5. **Possible actions to discuss:** 9 curated items (food, lifestyle, clinician discussions, and supplements that meet the bar below). Each separates *"does it help at all"* (best verified human design) from *"does the effect differ by genotype"* (tested-difference / tested-no-difference / not established). It shows sample size, population, dose/exposure, outcomes and harms, each with its verbatim quote, plus upper limits, adverse effects and interactions for supplements. Topics with no qualifying item are listed as **"No evidence-based personalized action."**

Plus an **evidence table** (every association and record), a **coverage table** (every curated site: tested / not on chip / no-call / mismatch, with notes), a **literature review layer** (PubMed candidates per topic, auto-classified by design, with animal-only / in vitro / not-yet-indexed flags and an auto-extracted sample size shown next to its snippet), and **Sources & audit** (versions, retrieval dates, and every claim the pipeline dropped).

Filters: section, minimum evidence strength, "only alleles I carry", free-text search. **Sensitive results** (APOE / Alzheimer disease) stay hidden until you explicitly choose to show them. **Optional context** (age range, ancestry, diagnoses, medications, allergies, dietary restrictions, goals) only adds flags. Each field explains what it changes, and none turns genotype into clinical advice.

### Supplement rules (enforced in `pipeline/build.ts`)

A supplement is included only with **(a)** a verified human RCT, meta-analysis or systematic review, and **(b)** a verified upper limit. Otherwise it is dropped and logged. The app never says a supplement helps *your genotype* unless a verified study tested a genotype difference, and then shows that study's caveats. No item recommends starting, stopping or changing medication.

## Synthetic data only

`src/demo/*.txt` and `tests/fixtures.ts` are synthetic. The demo files are generated by `scripts/make-demo.ts` from the bundle's own site definitions and are marked "SYNTHETIC DEMO FILE" in their headers. No real person's genotype is in this repository.

## What the MVP does not yet support

- **Coverage:** 22 curated sites, 12 trait topics, 9 interventions. This is not genome-wide ClinVar screening; a clean clinical section does **not** rule anything out.
- **Other input formats:** MyHeritage, FamilyTreeDNA, LivingDNA, VCF and whole-genome files are rejected with a clear message. So are genome build 36 files for position checks (they are still matched by rsID, with a warning).
- **Imputation or haplotypes** beyond APOE ε2/ε3/ε4 (which is stated as unphased, with the ε2/ε4 vs ε1/ε3 ambiguity).
- **Polygenic scores** and any **absolute risk** estimate.
- **Strand checks at palindromic sites** using study allele frequencies. Currently those sites are flagged, and effect-allele copies are not counted.
- **Pharmacogenomic dosing** (e.g. CPIC). ClinVar "drug response" records are shown as annotations only.
- **ClinVar somatic / oncogenicity classifications,** and submission-level detail beyond per-condition (RCV) aggregates.
- **Automated extraction** of dose, outcomes or harms from literature candidates. Candidates are a reading list; only curated, quote-verified studies feed section 5.
- **Other literature APIs** (Europe PMC, Semantic Scholar, OpenAlex). These would plug into `pipeline/literature.ts`.
- **An optional LLM summariser.** The pipeline is designed so one could summarise *verified bundle records only* (never genotypes), but none is included.
- **Localisation, accessibility audit, and saved sessions** (deliberately none: nothing is retained).
